# Watch boundary coverage

This is the authoritative map of extension-owned Watch behavior. Tests enter
through the real background message/native dispatcher and replace external
browser, clock and Instagram adapters. Runner tests execute the real processing
runner. A passing synthetic row does not establish Instagram or browser facts;
those results belong in [live verification](watch-live-verification.md).

CLI grammar, process stdout/stderr and exit status are owned by
`apps/cli/src/index.test.ts`. Shared version-2 request, result, progress, attention
and failure fixtures decode in all participants in
`packages/protocol/test/protocol.test.ts`. Native framing, disconnect cancellation
and version-skew forwarding are owned by `apps/native-host/src/index.test.ts`.

The scheduler also covers a missing browser startup event in "holds a new browser
session without a startup event and preserves the deadline across worker restarts".
A structural session marker gates the first worker of a browser session; a worker
restart keeps the existing deadline. [Chrome's storage contract](https://developer.chrome.com/docs/extensions/reference/api/storage#session)
clears session storage on browser restart and extension reload.

## Failure-code coverage

Each row uses the closed literals in `packages/protocol/src/failures.ts` and
`errors/contracts.ts`, canonical `watchFailure` construction, exhaustive
`FAILURE_PRESENTATION` recovery/diagnostic policy, structural Watch diagnostics,
the registry in [error-model.md](error-model.md), and the shared protocol fixtures.
`errors/watch-diagnostics.test.ts` independently checks every canonical shape and
round-trip. Watch domain failures use `watchFailure`; upstream failures use the
existing source/media/browser normalizers.
