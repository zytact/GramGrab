Implementation plan / workspace previews

Let the media choose its frame.

Replace the workspace's fixed landscape thumbnails with full-frame, aspect-aware previews arranged in a tightly packed responsive masonry layout. The compact popup remains deliberately unchanged.

01 / Intent

Resolved product contract

The feature follows media geometry rather than Instagram route labels. Stories and Highlights benefit immediately, while Reels and portrait posts receive the same correct behavior.

01

Actual ratio

Use trusted width and height metadata for every media type. Never infer portrait behavior from a URL type alone.

all mediaworkspace only
02

Full frame

Do not crop. Normal media fills a box matching its ratio. Unusually tall media is contained and centered within the height cap.

object-fit: contain
03

Tight masonry

Pack cards by height. Dense use of space takes priority over maintaining strict left-to-right numerical order.

~220px minimum

Fallback contract

When dimensions are absent or invalid, begin at 4:3. Read intrinsic image or video dimensions after load, then smoothly reflow the card. If intrinsic detection also fails, retain 4:3.

Responsive bound

Preview height is capped at min(70vh, 520px). The workspace targets roughly four, three, two, then one column as width decreases. The popup keeps its existing uniform 56 × 42px thumbnails.

04 / Build sequence

Vertical slices with testable seams

Keep transport, ratio resolution, and masonry placement separate. Each concern should remain understandable without knowing the others.

  1. Extend the shared media contract.

    Add optional width and height to fetch responses, popup/workspace items, and sanitized snapshots. Only positive finite pairs qualify as metadata ratios. Preserve backward compatibility with snapshots that omit both.

  2. Expose dimensions from the background.

    Include the dimensions already held by normalized MediaItem values in handleFetchMedia. Confirm image, video, sidecar, Story, Highlight, Reel, and profile-cover paths either provide dimensions or intentionally fall back.

  3. Introduce a pure ratio resolver.

    Create a small helper that returns metadata ratio when valid, intrinsic ratio when available, and 4 / 3 otherwise. Clamp neither normal ratios nor content; the renderer enforces only the visual height bound.

  4. Capture intrinsic geometry.

    On image load, read naturalWidth/naturalHeight. On video loadedmetadata, read videoWidth/videoHeight. Store fallback geometry by stable item index, clear stale measurements when a new fetch replaces the list, and avoid state updates when metadata already supplies a valid ratio.

  5. Build workspace-only ratio frames.

    Pass a CSS custom property or inline aspect-ratio to each workspace thumbnail. Use full-frame containment, the agreed maximum height, centered media, and a subtle resizing transition that respects prefers-reduced-motion. Leave popup selectors unchanged.

  6. Replace workspace grid placement with masonry.

    Use a deterministic, responsive column-placement implementation that assigns each card to the currently shortest column while retaining DOM semantics and stable item identity. Recalculate when column count, container width, item ratio, or card content height changes. Avoid relying on experimental CSS masonry support.

  7. Harden resizing and cleanup.

    Observe the workspace container rather than the whole window, debounce or batch layout measurement with animation frames, disconnect observers on unmount, and ensure fallback preview replacement cannot leave stale intrinsic dimensions behind.

06 / Verification

Prove both data and layout

Automated checks cover deterministic behavior. Browser verification covers computed sizing and dense visual packing that jsdom cannot faithfully model.

Automated cases

  • Valid metadata wins over intrinsic dimensions.
  • Missing, zero, negative, infinite, or one-sided metadata falls back safely.
  • Image load and video metadata events update the ratio.
  • Failed detection remains at 4:3 without throwing.
  • Workspace snapshots retain dimensions; data URLs remain excluded.
  • Compact popup dimensions and row layout remain unchanged.
  • Selection, preview fallback, and frame export still work.

Browser matrix

  • Mixed 16:9, 4:3, 1:1, 4:5, and 9:16 fixtures.
  • Four-, three-, two-, and one-column widths.
  • 520px and 70vh height constraints.
  • No crop in images or video poster/frame content.
  • Stable packing after delayed media loads and resize.
  • Chrome and Firefox MV3 builds.
  • Realistic Story and Highlight URLs when authenticated access is available.

07 / Risk register

Likely failure modes

The implementation should solve these directly, not hide them with route-specific exceptions.

Layout churnUnknown media ratios arrive after first paint.Metadata-first sizing, 4:3 placeholder, batched intrinsic updates, restrained transition.
Stale stateA replaced fetch reuses item indexes and old measurements.Reset intrinsic geometry with each fetched media set and key state to the current item identity.
Observer loopsMeasuring cards changes columns, triggering repeated layout.Derive column count from container width, batch measurement, and commit only changed placements.
Visual orderTight packing differs from numerical and keyboard order.Keep DOM order and numbered labels stable; treat masonry placement as visual only.
Bad geometryInstagram sends missing or malformed dimensions.Central positive-finite validation plus intrinsic and 4:3 fallback chain.
Huge cardsOne-column 9:16 media dominates the viewport.Apply min(70vh, 520px), contain content, and preserve access to card controls.
08 / Completion

Definition of done

Every workspace media card presents the complete downloadable media at its real aspect ratio when dimensions are known, recovers accurately from missing metadata through intrinsic measurement, packs responsively into dense masonry columns, respects the agreed height bound and reduced-motion preferences, leaves the compact popup unchanged, and passes the full automated and browser verification matrix.
